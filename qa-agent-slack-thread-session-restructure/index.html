QA 에이전트 Slack 스레드 개선과 세션 구조 전환

26년 03월 20일
  • #journal

파이프라인 재구성하고 병렬 실행까지 붙인 뒤라, 이번에는 결과를 돌려주는 쪽과 세션 관리 쪽을 다듬는 작업이 이어졌다.

QA 에이전트가 돌린 결과를 Slack으로 쏴주는 부분이랑, 실행 환경 세션을 어떻게 관리할지가 주된 주제였다.

부수적으로 영구 저장소 구조도 정리했다.

Slack 결과 링크와 스레드

링크 일관성

QA 에이전트가 테스트를 돌리고 나면 결과 페이지 링크를 Slack 스레드로 쏴준다.

근데 이 링크가 어디서 만들어지는지가 일관적이지 않았다.

실행 흐름 여러 곳에서 링크를 조립하다 보니까, 같은 결과 페이지인데도 문맥에 따라 URL 형태가 미묘하게 달라지는 문제가 있었다.

링크 생성 로직을 한 곳으로 모았다.

이제 결과 페이지 URL은 단일 경로에서 만들어지고, 어디서든 동일한 형태로 내려온다.

스레드 제목에 시트 이름

기존에는 Slack 스레드 제목이 실행 컨텍스트 기반이었다.

그러니까 스레드가 올라오면 “이게 어떤 시트에 대한 결과인지”를 스레드 제목만 보고 알 수가 없었다.

매번 스레드를 열어봐야 했다.

그래서 스레드 제목에 시트 이름을 노출하도록 바꿨다.

Slack 알림만 봐도 어떤 시트의 QA가 돌아갔는지 바로 알 수 있으니까, 결과를 빨리 파악할 수 있어서 꽤 편하다.

opencode 세션 구조 전환

일회성 CLI의 한계

그 전까지 실행 환경 세션은 일회성 CLI로 돌아갔다.

실행할 때마다 CLI를 새로 띄우고, 끝나면 세션이 날아가는 구조다.

한 번 실행할 때는 괜찮은데, planning이랑 실행을 분리하려고 하니까 한계가 드러났다.

planning 결과를 실행 쪽이 이어받으려면 세션이 살아 있어야 하는데, 일회성 CLI에서는 그게 안 된다.

서버 기반 세션 구조로 전환했다.

planning 세션과 실행 세션 분리

세션을 용도별로 나눴다.

planning 전용 세션 1개를 두고, 실행 lane마다 별도 세션을 할당했다.

planning 세션에서 실행 계획을 수립하면, 각 실행 세션이 그 계획을 받아서 돌리는 구조다.

세션이 분리되니까 planning과 실행 사이에 상태가 섞이지 않는다.

실행 lane끼리도 각자 세션을 가지니까 병렬로 돌아가는 동안 서로 간섭이 없다.

영구 저장소 구조 개선

코드 저장소 외부로 통합

QA 에이전트가 실행되면서 fixture knowledge, 에이전트 스킬, planning 캐시 같은 것들을 쌓는다.

근데 이게 다 코드 저장소 안에 섞여 있었다.

코드 저장소 안에 실행 산출물이 있으니까 git 상태가 지저분해지고, 컨테이너를 다시 띄울 때마다 캐시가 날아가는 문제도 있었다.

이 영구 저장소들을 코드 저장소 외부로 빼서 하나로 통합했다.

이제 코드 저장소는 코드만 들어있고, 실행 관련 산출물은 별도 경로에 쌓인다.

컨테이너를 재생성해도 영구 저장소는 유지되니까 캐시가 사라지지 않는다.

마무리

결과를 돌려주는 부분부터 세션 구조까지 정리하고 나니, 실행 파이프라인이 앞뒤로 깔끔하게 이어지는 느낌이다.

Slack 스레드 제목에 시트 이름이 보이는 건 사소해 보이는데 실사용에서 체감이 꽤 크다.

세션 분리도 planning과 실행을 독립적으로 다룰 수 있게 해주니까, 앞으로 실행 lane을 더 늘리거나 역할을 세분화할 때 유연하게 대응할 수 있을 것 같다.
