에이전트 모델 분산을 재편하고 스모크 합격률을 끌어올린 날이었다.

## 모델 분산

5개 에이전트가 2개 모델만 쓰고 있었다.

플래너와 실행자는 비싼 모델, 나머지도 같은 모델을 공유하고 있었다.

비용이 집중되고, 한 모델에 장애가 나면 전체가 멈추는 리스크가 있었다.

4개 모델로 균등 분산했다.

Inspector와 클리너는 glm-5를, 스킬 크리에이터와 시트 작성자는 glm-4.7을 쓴다.

각 에이전트의 역할에 맞는 모델을 배정했다.

추론이 중요한 에이전트는 더 비싼 모델을, 단순 작업은 가벼운 모델을 쓴다.

## Serena MCP 평가

Serena MCP라는 코드 탐색 도구를 평가했다.

Rails를 지원하지 않고, 초기화에 30~120초가 걸리고, 500MB를 추가로 먹는다.

기존에 쓰고 있는 ast-grep + grep + read 조합이 더 가볍고 빠르다.

Serena를 도입하지 않고 기존 도구를 유지하기로 했다.

> 도구를 바꾸는 건 새로운 도구가 확실한 이점이 있을 때만 해야 한다. 그냥 새롭다는 이유로 바꾸면 복잡도만 늘어난다.

## explore 에이전트 통합

explore 에이전트를 task 시스템에 통합했다.

기존에는 explore를 별도로 호출해야 했는데, task 권한에 explore를 허용하는 변경 한 줄로 통합했다.

이제 다른 에이전트가 task를 통해 explore를 자연스럽게 호출할 수 있다.

## 스모크 합격률 60.6%

33개 케이스로 스모크 테스트를 13회 반복했다.

합격률이 18.2%에서 시작해서 60.6%까지 올랐다.

7개 파일을 수정하면서 점진적으로 올렸다.

### 합격률 향상 요인

모델 분산으로 각 에이전트가 안정적으로 동작하게 된 게 크다.

한 모델에 장애가 나도 다른 모델이 받아서 실행이 멈추지 않는다.

explore 통합으로 코드 탐색이 더 자연스러워진 것도 효과가 있었다.

## 마무리

스모크 60.6%는 저번 주 60.7%와 비슷한 수준이지만, 케이스 수가 28개에서 33개로 늘어난 상태에서 달성한 거다.

더 많은 케이스를 커버하면서도 합격률을 유지했다.
