ClawMux의 라우팅 파이프라인을 완성한 날이었다.

6개 API 포맷 어댑터, 크로스 프로바이더 라우팅, 세션 스토어까지 한 번에 구현했다.

## 6개 API 어댑터

LLM provider마다 API 포맷이 다르다.

OpenAI 포맷, Anthropic 포맷, Google 포맷 등 각자 요청/응답 구조가 다르다.

ClawMux는 이런 이기종 API 사이에서 라우팅을 해야 하니까, 각 provider의 포맷을 변환하는 어댑터가 필요했다.

6개 provider에 대한 어댑터를 구현했다.

어댑터는 요청을 provider 포맷으로 변환하고, 응답을 ClawMux 공통 포맷으로 역변환한다.

## 크로스 프로바이더 라우팅

요청이 들어오면 분류기가 복잡도를 판단하고, 적절한 provider로 라우팅한다.

문제는 provider 간 포맷 차이다.

OpenAI 포맷으로 들어온 요청을 Anthropic으로 보내려면, OpenAI 포맷을 Anthropic 포맷으로 변환해야 한다.

이 변환을 어댑터가 처리한다.

사용자는 자기가 쓰는 provider 포맷으로 요청을 보내고, ClawMux가 알아서 최적의 provider로 라우팅하고 포맷을 변환한다.

## 시맨틱 분류기 전환

분류기를 업그레이드했다.

기존에는 14차원 키워드 스코어러를 썼다.

14개 키워드 카테고리에 대해 점수를 매겨서 4단계(LIGHT/MEDIUM/HEAVY/QUICK)로 분류했다.

이걸 임베딩 기반 시맨틱 분류기로 바꿨다.

키워드 매칭이 아니라 요청의 의미를 임베딩 벡터로 표현하고, 미리 정의된 카테고리 중심점과의 거리로 분류한다.

### Naive Bayes에서 임베딩으로

처음에는 Naive Bayes로 시작했다.

빠르고 간단하지만, 단어의 의미를 이해하지 못한다.

"리팩토링"과 "구조 개선"은 같은 의미인데 다른 단어라서 다르게 분류된다.

임베딩 모델을 쓰면 의미가 비슷한 단어를 비슷한 벡터로 표현하니까, 다른 단어라도 같은 의미면 같은 카테고리로 분류된다.

로컬 임베딩 모델을 써서 API 호출 없이 분류한다.

## 세션 스토어

요청 간 세션을 유지하는 세션 스토어를 구현했다.

같은 대화의 요청들은 같은 세션으로 묶어서, 이전 요청의 컨텍스트를 재사용할 수 있다.

컨텍스트 재사용으로 반복되는 요청의 토큰 사용량을 줄였다.

## 마무리

6개 어댑터와 크로스 프로바이더 라우팅이 완성되니까 ClawMux가 실제로 쓸 만해졌다.

시맨틱 분류기 전환으로 분류 정확도도 크게 올랐다.
