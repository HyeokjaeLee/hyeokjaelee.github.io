재시도를 아무리 해도 전부 실패했다는 뜻이다.

이걸 해결한 날이었다.

## 문제 진단

재시도가 0% 성공이라는 건 재시도 자체가 잘못되었다는 거다.

원인을 추적해보니 스킬 주입 race condition이 핵심이었다.

재시도할 때 에이전트에게 필요한 스킬을 주입하는데 이 주입 타이밍이 실행 타이밍과 겹치고 있었다.

스킬이 완전히 로딩되기 전에 에이전트가 실행을 시작해버리니까 스킬 없이 실행한 셈이 됐다.

그러니까 당연히 실패한다.

## 스킬 주입 race condition 수정

스킬 주입이 완료된 것을 확인한 뒤에 실행을 시작하도록 순서를 보장했다.

간단해 보이지만, 비동기로 동작하는 시스템에서는 이런 순서 보장이 꽤 까다롭다.

주입 완료 시그널을 명시적으로 보내고 실행 에이전트는 시그널을 받아야 시작하도록 바꿨다.

테스트도 추가했다.

이런 타이밍 버그는 재현이 어려워서 테스트 없이는 다시 발생했을 때 원인을 찾기 힘들다.

## Inspector 서브에이전트 배포

qa-inspector 서브에이전트를 배포했다.

Inspector의 역할은 blocked 케이스의 원인을 분석하는 거다.

기존에는 재시도할 때 실행 에이전트가 스스로 원인을 분석하면서 재시도했다.

실행과 분석을 같은 에이전트가 하다 보니까 컨텍스트가 섞이고 분석 품질이 떨어졌다.

Inspector가 분석을 전담하니까 실행 에이전트는 실행에만 집중할 수 있게 됐다.

Inspector가 blocked 원인을 분석하고 재시도 전략을 수립해서 실행 에이전트에 전달한다.

## 스크린샷 생성 누락

스크린샷이 간헐적으로 누락되는 버그를 진단했다.

실행이 끝났을 때 스크린샷이 없으면 결과 리포트에서 증거가 사라진다.

원인은 실행 흐름 중 스크린샷 생성 단계가 우선순위에서 밀리는 것이었다.

todowrite 체크리스트로 방지책을 마련했다.

실행 흐름에 스크린샷 생성을 필수 체크리스트 항목으로 넣고 누락 시 경고를 내보낸다.
