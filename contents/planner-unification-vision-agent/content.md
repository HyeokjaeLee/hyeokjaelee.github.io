## [journal] 쪼개진 플래너를 하나로 모으는 결정

QA Agent의 planning 파이프라인이 점점 무거워지고 있었다.
처음엔 3단계로 나눠 잡 분리가 깔끔하다고 생각했는데, 실제로 돌려보니 단계 사이 통신 비용이 더 컸다.
각 단계가 서로의 결과를 기다리고 다시 직렬화하고 다시 파싱하는 과정이 쌓이니 한 사이클이 길어졌다.

단일 qa-planner로 합치기로 했다.
3단계를 한 흐름으로 묶고, 중간에 끼어 있던 junior / code-viewer / skeleton 관련 코드를 싹 지웠다.
정리하고 보니 36개 파일, 약 1200줄이 사라졌다.
코드가 줄어드는 리팩토링은 기분이 좋다.

## [journal] qa-vision 서브에이전트

플래너를 통합하면서 스크린샷 처리도 같이 정리했다.
기존엔 메인 에이전트가 텍스트 DOM만 보고 판단하다 보니 시각적으로는 명확한 실패를 놓치는 경우가 있었다.
버튼이 가려져 있거나 모달이 떠 있거나 레이아웃이 깨진 경우가 대표적이다.

qa-vision이라는 서브에이전트를 붙였다.
메인 에이전트가 스크린샷을 찍으면 qa-vision이 그 이미지를 보고 시각적 단서를 뽑아 플래너에게 돌려준다.
구조상 비용이 하나 더 붙지만 디버깅 시간이 줄어드는 효과가 더 크다.

스크린샷을 의무화한 것도 같은 맥락이다.
이제는 모든 판단 시점에 스크린샷이 남는다.
나중에 "왜 그렇게 판단했지"가 궁금할 때 이미지로 되짚을 수 있다.

## [journal] Docker 메모리 고갈, 결국 원인을 잡았다

병목 코드를 정리하다 보니 메모리 문제가 수면 위로 올라왔다.
호스트 메모리 8GB 중에 qa-agent가 5GB 이상을 잡아먹고 있었다.

원인은 Chromium 동시 실행이었다.
한 번에 Chromium 인스턴스가 4개 떠 있었고 각각이 수백 MB씩 가져갔다.
CDP 통신이 지연되면서 응답이 꼬이고 결국 SIGKILL이 연쇄로 터졌다.
로그만 보면 어디서 죽었는지 알 수 없는 상태였다.

정리한 건 두 가지다.
Chromium 환경변수를 런타임에서 한 번에 주입하도록 묶고, Dockerfile에 중복으로 들어 있던 설정을 제거했다.
인스턴스 수가 줄고 CDP 지연도 사라졌다.

세션 ID 추출이 자꾸 실패한 것도 같이 잡았다.
원인은 세 가지였다.
LLM이 idle 상태를 오판한 것, sharp 패키지가 빠져 있던 것, 동시 요청이 과부하를 일으킨 것.
하나씩 고치니 추출 성공률이 확 올라갔다.

## [journal] 줄이고 나니 보이는 것

한 번에 정리하니 체감이 확 다르다.
코드량이 줄고 메모리가 안정되고 스크린샷이 남으니 재현 디버깅이 쉬워졌다.
"어디서 문제가 터졌는지 모르겠다"는 상태가 사라진 게 가장 크다.

다음엔 qa-vision 쪽 비용을 좀 더 줄여볼 생각이다.
이미지를 찍을 때마다 서브에이전트가 도는 구조라 빈번한 호출을 어떻게 묶을지가 과제다.
