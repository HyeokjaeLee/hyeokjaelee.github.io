## 역량진단리포트를 코스 전체로 풀기

하루의 대부분을 역량진단리포트 기능 확장에 썼다.
특정 코스 매니저만 볼 수 있던 기능을 일반 코스 매니저까지 풀어달라는 요구가 들어왔다.
단순히 권한 하나 풀면 끝일 줄 알았는데 의존성이 의외로 넓었다.

라우터 권한 가드부터 매니저 전용 배지, 프로필 API의 노출 필드까지 한꺼번에 손 봐야 했다.
가드 로직을 공통 권한으로 바꾸고 코스 카드에 붙어있던 전용 칩을 떼냈다.
내부 계정 여부는 API 응답 필드로만 판별하도록 노출 제어를 옮겼다.

PR은 한 번에 머지되지 않았다.
`StickyBanner` 컴포넌트의 표시 버튼 조건이 충돌나서 수동으로 합쳤고 CI typecheck는 테스트 fixture 세 곳에 `isInternalAccount: false`를 추가해서 넘겼다.
배포 직전에 매니저 권한 키 대소문자 버그와 코스 카드 칩 하나 잘못 들어간 것도 잡아냈다.
alpha 배포까지 무사히 붙였다.

리뷰 피드백은 UI 디테일 수준이라 큰 구조 변경 없이 반영했다.

## Figma 분석 에이전트 분리

한참 쓰던 Notion 기획 → 구현 계획 스킬에 Figma 입력을 얹었다.
기존엔 텍스트 기반 기획 문서만 다뤘는데 디자인 링크만 넣어도 구현 계획이 나오게 만들고 싶었다.

핵심은 Figma 도구를 메인 에이전트에서 직접 들고 있지 않고 Gemini 서브에이전트에 위임한 점이다.
메인 에이전트는 URL에서 메타데이터만 뽑고 프레임 트리 순회와 11개 섹션 분석 리포트는 서브에이전트로 넘겼다.
컨텍스트 예산 아끼기엔 이 분리가 효과적이었다.

경로 컨벤션도 같이 정리했다.
폴더명은 Jira 키 기반, 파일명은 Notion 문서 제목 기반으로 분리하고 제목 정규화 7단계(인덱스 마커·이모지·브래킷·Jira 키 제거, 금지문자 치환, 길이 제한)를 붙였다.
어디까지나 규칙이 정해져 있어야 파일명 충돌이 안 난다.

## 옵시디언 볼트 재구성 마무리

`20_Projects` 디렉토리가 199개 파일 평면으로 묵고 있었다.
아무리 검색이 빨라도 훑어보기가 어려워 분류 체계를 손보기로 했다.

먼저 `type`/`area` 이원 분류를 `category` 단일 필드로 통합했다.
63개 노트를 재분류하고 legacy 필드를 떼냈다.
그 뒤 199개 파일을 11개 카테고리 디렉토리로 쪼갰다 — QA 자동화, 메인 클라이언트, 코딩 에이전트, 옵시디언 같은 식이다.

이동은 `obsidian move` 명령으로 wikilink 무결성을 자동 보존하게 했다.
4개 병렬 에이전트를 돌려 끊어진 링크 7건만 수동으로 복구했다.

## 마무리하며

코드 변경은 배포 직전까지가 진짜라는 걸 이번에도 느꼈다.
기능 자체는 권한 하나 넓히는 거였지만 CI·테스트·권한 키·UI 칩까지 손 안 대는 곳이 없었다.
