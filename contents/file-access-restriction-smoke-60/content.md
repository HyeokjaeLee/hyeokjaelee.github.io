QA 에이전트의 보안 경계를 정리하고 스모크 테스트 목표를 달성한 날이었다.

## 파일 직접 접근 제거

플래너, 실행자, 시트 작성자가 파일 시스템에 직접 접근할 수 있었다.

코드를 읽거나 디렉토리를 탐색하는 등 파일 접근이 필요한 경우가 있는데, 이걸 각 에이전트가 직접 하고 있었다.

문제는 보안과 일관성이다.

각 에이전트가 자기 멋대로 파일을 읽으면 접근 권한 제어가 안 된다.

파일 탐색 로직이 에이전트마다 달라서 중복 코드가 많았다.

파일 탐색을 explore 서브에이전트에만 위임했다.

이제 다른 에이전트는 파일에 직접 접근하지 못하고, explore를 통해서만 코드나 디렉토리를 탐색할 수 있다.

접근 권한이 한 곳으로 집중되니까 통제하기 편해졌다.

explore가 전담하니까 탐색 품질도 올라갔다.

이전에는 각 에이전트가 대충 파일을 읽었는데, 이제는 explore가 체계적으로 탐색한다.

## 스모크 테스트 60% 달성

스모크 테스트에서 28개 케이스 중 17개가 통과했다.

60.7%다.

목표가 60%였는데 첫 실행에서 달성했다.

한 달 전 스모크 시작 시 50%에서 시작했으니까 10% 포인트가 올랐다.

### 통과율 향상 요인

통과율이 올라간 건 앞선 작업들의 복합 효과다.

DAG 스케줄링으로 의존성 관리가 정확해졌다.

의존성이 정확해야 실패한 케이스의 하위 케이스를 제대로 blocked 처리할 수 있다.

의존성이 틀리면 정상적으로 실행해야 할 케이스가 blocked 되거나, 실패한 케이스의 하위가 무의미하게 실행된다.

Inspector가 blocked 원인을 분석해서 재시도 품질이 올라갔다.

이전에는 재시도할 때 이전 실패 원인을 모른 채로 다시 실행했다.

이제는 Inspector가 "이전에 로그인 버튼을 못 찾아서 실패했다" 같은 분석을 제공해서, 재시도가 더 똑똑해졌다.

Fixture Knowledge로 이전 실행 지식을 재사용해서 동일한 실패를 반복하지 않는다.

파일 접근 제거로 explore가 전담해서 코드 탐색 품질이 올라간 것도 효과가 있었다.

## ClawMux 정리

ClawMux 문서를 보강했다.

`confidenceThreshold` 설정 문서를 추가하고, Session Logger를 CREATE-only로 개선했다.

한국어 응답 설정을 추가했다.

LLM이 영어로 응답하는 경우가 있어서 기본 응답 언어를 한국어로 고정했다.

Docker 리소스를 정리해서 34GB를 확보했다.

오래된 이미지와 컨테이너가 쌓여 있어서 디스크가 가득 차고 있었다.

## 마무리

스모크 60%는 의미 있는 마일스톤이다.

여기서 더 올리려면 근본적인 케이스 품질 개선이 필요하다.
