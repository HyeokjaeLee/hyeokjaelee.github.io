## 같은 축 위에 놓인 두 작업

이날 들어온 두 작업은 티켓 번호는 달랐지만 사실 같은 축 위에 있었다.
코스 유형이라는 분기 조건 하나가 매니저 권한과 주차 노출 범위, 리포트 대상까지 줄줄이 바꾸는 구조였다.
그래서 두 작업을 별개로 보지 않고 한 흐름에서 같이 다뤘다.

## 코스 유형별 주차 범위 정리

첫 작업은 새 코스 유형이 추가됐을 때 1주차가 어떻게 노출되는지 정리하는 일이었다.
코스 생성 모달과 기본 정보 관리 화면에 코스 유형별로 다른 분기 로직이 들어가야 했다.
정리하다 보니 UI 분기로 끝나는 일이 아니더라.
코스 유형이 바뀌면 매니저가 갖는 권한도 따라 바뀌기 때문이다.
그래서 매니저 권한 제어 설계까지 같이 들어갔다.
결과는 문서 정리와 분기 로직 설계까지 마무리한 형태.
코드를 붙이는 건 다음 단계로 넘겼다.

## 역량진단리포트, 모든 코스로 확장

두 번째 작업은 역량진단리포트를 특정 코스 유형에서 모든 코스로 확장하는 마무리였다.
이전에 달아둔 PR이 있었고, 이번에는 코드리뷰 피드백을 반영하는 차례였다.
리뷰 반영하랴 CI 실패 잡으랴 꽤 오래 들여다봤다.
4개 앱 패치 버전을 올렸고, alpha 배포만 5번 넘게 돌렸다.
배포가 반복되는 동안 CI 로그를 계속 들여다보게 됐다.
마지막에는 PR CI에서 초록불이 떴다.

## 같은 분기, 다른 마무리

두 작업 모두 코스 유형에 따른 분기라는 점에서는 같았다.
다만 하나는 설계와 범위 정리 단계에서 멈췄고, 하나는 배포까지 끝난 마무리.
코스 유형 분기 하나가 프론트엔드 전반에 어떻게 퍼지는지를 하루 안에 양쪽에서 본 느낌이었다.
다음에는 이 분기 조건을 한 곳에서 더 명확하게 모아보고 싶다는 생각이 들었다.
