에이전트 구조를 모노리식에서 멀티 에이전트로 전면 재설계한 날이었다.

지금까지는 하나의 큰 코드베이스에서 모든 에이전트가 같은 공간에 있었다.

역할 분리는 해두었지만 물리적으로는 한 덩어리라서, 하나를 고치면 다른 것도 영향을 받았다.

## 멀티 에이전트 디렉토리 재설계

에이전트별로 독립적인 디렉토리를 가지도록 구조를 바꿨다.

`src/shared/`에 공통 타입과 유틸리티를 두고, 각 에이전트는 자기 디렉토리 안에서만 동작한다.

Slack 라우팅 계층을 도입해서, Slack 메시지가 들어오면 어떤 에이전트가 처리할지 라우팅한다.

각 에이전트가 독립적이니까 하나를 수정해도 다른 에이전트에 영향이 가지 않는다.

## 2-Phase Retry

재시도 로직을 2단계로 분리했다.

1회차에는 전체 케이스를 한 번 실행한다.

실행 결과에서 blocked 케이스만 추려서 2회차에 병렬로 재시도한다.

전체를 다시 실행하지 않으니까 재시도 비용이 크게 줄었다.

blocked 케이스만 모아서 병렬로 돌리니까 2회차 실행 시간도 짧다.

> 기존에는 재시도할 때 전체를 다시 돌렸다. 케이스 30개 중 3개가 blocked면 27개를 또 실행하는 낭비가 있었다.

## Managed Skills 파이프라인

에이전트가 실행 중 만든 스킬을 자동으로 관리하는 파이프라인을 만들었다.

기존에는 프로그래밍 방식으로 스킬을 생성했다.

이걸 서브에이전트가 실행 결과에서 스킬을 추출하고, 클리너가 검증하고, 승격하는 파이프라인으로 바꿨다.

사람이 개입하지 않아도 실행 지식이 자동으로 스킬로 축적된다.

## session-logger 플러그인

OpenCode 플러그인으로 session-logger를 구현했다.

세션 로그를 60초 디바운스로 기록한다.

서브에이전트가 재사용할 수 있고, 컨텍스트 압축도 지원한다.

이전에는 세션 로그가 흩어져 있어서 디버깅할 때 찾기 어려웠는데, 플러그인으로 통합하니까 한 곳에서 관리된다.

## 마무리

멀티 에이전트 구조로 전환하고 나니까 각 에이전트를 독립적으로 개발하고 테스트할 수 있게 됐다.

2-Phase Retry는 실행 비용 절감 효과가 확실하다.
