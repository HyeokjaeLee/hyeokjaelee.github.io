QA 에이전트의 구조를 모노리식에서 멀티 에이전트로 재설계한 날이었다.

코드가 한 곳에 다 모여 있으니까 변경할 때마다 사이드 이펙트가 나왔다.

재설계와 동시에 재시도 체계도 바꿨다.

## 모노리식에서 멀티 에이전트로

기존에는 모든 에이전트 코드가 하나의 큰 파일에 있었다.

플래너, 실행자, 리포터, 체커가 같은 파일에서 각자의 역할을 처리했다.

코드가 커지면서 문제가 생겼다.

플래너 로직을 수정하면 실행자에 영향을 줄 수 있다.

역할 간 경계가 명확하지 않으니까 디버깅할 때 어디서 문제가 왔는지 추적이 어려웠다.

각 역할을 별도 디렉토리로 분리했다.

`src/shared/`에 공통 타입과 유틸리티를 두고, 각 에이전트는 자기 디렉토리에서 독립적으로 동작한다.

Slack 라우팅 계층도 별도로 분리했다.

결과 메시지를 조립하고 Slack으로 보내는 건 라우팅 계층에서만 처리한다.

## 2-Phase Retry

재시도 체계를 2단계로 나눴다.

Phase 1에서 전체 케이스를 한 번 실행한다.

실행이 끝나면 blocked 케이스만 모은다.

Phase 2에서 blocked 케이스만 병렬로 재시도한다.

이전에는 실패할 때마다 즉시 재시도했다.

즉시 재시도는 문제가 있다.

일시적인 장애라면 잠시 기다렸다가 재시도하는 게 낫다.

그리고 전체 실행이 끝난 뒤에 상황을 종합적으로 판단하는 게 더 정확하다.

2-Phase로 나누니까 재시도 효율이 올라갔다.

blocked 케이스만 선별해서 재시도하니까 불필요한 재실행이 줄어든다.

## Managed Skills 파이프라인

스킬 생성 방식을 바꿨다.

이전에는 프로그래밍 방식으로 스킬을 생성했다.

코드로 스킬을 만들다 보니 스킬 품질이 일정하지 않았다.

서브에이전트가 실행 중에 학습한 지식을 스킬로 만들고, 클리너가 검증하고, 검증을 통과한 것만 승격하는 파이프라인을 만들었다.

승격된 스킬만 실제 실행에 사용된다.

검증을 거치지 않은 스킬은 사용되지 않는다.

이 파이프라인이 들어오니까 스킬 품질이 안정화됐다.

## session-logger 플러그인

OpenCode에 session-logger 플러그인을 구현했다.

서브에이전트의 실행 로그를 기록하는 플러그인이다.

60초 디바운스로 로그를 기록한다.

60초 동안 쌓인 로그를 하나의 배치로 저장한다.

실시간으로 매 액션마다 기록하면 I/O 부하가 크니까 디바운스를 적용했다.

서브에이전트 재사용과 컨텍스트 압축 기능도 넣었다.

로그가 너무 길어지면 컨텍스트 압축으로 요약한다.

> 로깅은 디버깅의 기반이다. 로그가 없으면 "왜 이 케이스가 실패했지?"라는 질문에 답할 수 없다. 하지만 로깅이 너무 빈번하면 성능이 떨어지니까 디바운스가 필요하다.

## AI 에이전트와 Obsidian CLI

AI 에이전트와 Obsidian CLI를 연결하는 지식 관리 파이프라인을 정리했다.

에이전트가 실행 중에 얻은 지식을 Obsidian에 자동으로 기록하는 흐름이다.

나중에 회고하거나 위키에서 검색할 수 있다.
