## [journal] ClawMux 초기 뼈대 잡기

ClawMux의 핵심 파이프라인을 한 번에 몰아서 만들었다.

6개 API 포맷 어댑터, 크로스 프로바이더 라우팅, 세션 스토어까지 한 번에 구현했다.
한 번에 처리한 양이 꽤 되는데, 하나씩 붙여나가니 생각보다 매끄럽게 돌아갔다.

## 어댑터 6종

OpenClaw(이하 `openclaw`)가 Anthropic 포맷으로 요청을 밀어 넣는다.
반대쪽에는 ZAI, Codex, OpenAI 등 제각각 포맷이 다른 프로바이더가 붙어 있다.

그래서 어댑터 레이어를 하나 깔았다.

- 들어오는 Anthropic 요청을 각 프로바이더 포맷으로 변환
- 응답을 다시 Anthropic 포맷으로 역변환

6개 어댑터를 일관된 인터페이스로 묶어두니, 새 프로바이더를 붙일 때 구조를 건드릴 필요가 없다.
변환 규칙만 추가하면 끝이다.

## 크로스 프로바이더 라우팅

여기가 제일 재밌던 부분이다.

Anthropic 포맷 → OpenAI 포맷 → ZAI 호출 → OpenAI 응답 → Anthropic 포맷.
왕복 변환이 필연적으로 일어나는 구조다.
ZAI가 OpenAI 호환 API만 제공하기 때문에 어쩔 수 없다.

라우팅 테이블에서 프로바이더를 고르면, 어댑터가 알아서 포맷을 맞춘다.
크로스 프로바이더 여부를 감지하는 브랜치 하나로 깔끔하게 떨어졌다.

> 포맷 변환 로직이 금방 비대해질 것 같아, 변환 함수는 프로바이더별로 파일을 나눴다.
> 하나에 몰아넣으면 나중에 못 읽는다.

## 세션 스토어

요청 사이에 상태를 들고 있어야 하는 부분이 있었다.

세션 ID 기준으로 대화 컨텍스트를 보존하고, 같은 세션의 후속 요청이 들어오면 이어 붙이는 식이다.
단순한 key-value 맵으로 시작했는데, 지금은 이 정도면 충분하다.

나중에 세션 만료·TTL 정책이 필요하면 그때 손보려고 한다.

## 한 회차 마무리

초기 구현치고는 덩치가 컸다.

어댑터 인터페이스를 처음부터 제대로 잡아둔 게 가장 잘한 선택이었던 것 같다.
나머지는 거기에 맞춰서 채워 넣는 일이었다.

다음엔 분류기를 다듬고, reasoning-disable 처리를 붙여볼 생각이다.
