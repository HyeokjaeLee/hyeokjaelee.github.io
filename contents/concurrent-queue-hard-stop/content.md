QA 에이전트가 여러 케이스를 동시에 실행할 때 큐 관리가 필요해졌다.

병렬 실행을 도입하니까 실행 순서와 리소스 제어가 문제였다.

## 동시 실행 큐

DAG 스케줄러가 실행 가능한 케이스를 큐에 넣으면, 가용한 lane이 큐에서 케이스를 꺼내서 실행한다.

문제는 큐가 무한정 커질 수 있다는 거다.

모든 케이스가 동시에 실행 가능해지면, 한 번에 너무 많은 브라우저가 뜨면서 메모리가 터진다.

실행 큐에 최대 동시 실행 수를 제한했다.

lane 수만큼만 동시 실행되고, 나머지는 큐에서 대기한다.

## hard stop

실행 중인 케이스가 응답 없이 멈추는 경우가 있었다.

LLM이 응답하지 않거나, 브라우저가 페이지 로딩에서 무한 대기에 빠지거나.

이런 케이스를 방치하면 전체 실행이 끝나지 않는다.

hard stop 기능을 구현했다.

각 케이스에 타임아웃을 설정하고 시간이 초과되면 강제로 종료한다.

강제 종료 시 브라우저 세션도 같이 정리해서 좀비 프로세스가 남지 않게 한다.

> hard stop은 잔인해 보이지만 없으면 안 된다. 하나의 멈춘 케이스가 전체 실행을 인질로 잡기 때문이다.

## Graviton 마이그레이션

Alpha 환경을 Graviton 인스턴스로 마이그레이션했다.

ARM64 아키텍처라서 일부 npm 패키지가 호환되지 않는 문제가 있었다.

호환되는 버전으로 올리거나 대체 패키지를 찾아서 해결했다.

## qa-sheet-writer 개선

qa-sheet-writer의 `skipAgentTest` 판단 기준을 정리했다.

에이전트가 자동화할 필요가 없는 케이스를 명확히 구분한다.

메모 작성 지침도 개선했다.

PM이 결과를 읽을 때 필요한 정보가 무엇인지 기준을 잡고 그 기준에 맞춰서 메모를 작성하도록 했다.

## 마무리

동시 실행 큐와 hard stop으로 실행 안정성이 크게 올라갔다.

이제 케이스가 멈춰도 전체 실행이 끝나지 않는 일이 없다.
