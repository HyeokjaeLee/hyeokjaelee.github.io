업무 프로젝트 코스 분류 계획과 빌드 인프라를 개선한 날이었다.

## 코스 분류 추가 구현 계획

코스 생성 모달과 수강 설정 파트에서 완료율과 순차수강 옵션을 추가하기 위한 계획을 수립했다.

완료율은 학생이 전체 강의 중 몇 %를 완료했는지 보여주는 기능이다.

순차수강은 이전 강의를 완료해야 다음 강의가 잠금 해제되는 기능이다.

이 두 가지 옵션이 코스 유형에 따라 다르게 동작해야 한다.

### Figma 대비 누락 분기

Figma 디자인과 비교해서 누락된 분기를 찾아 반영했다.

디자인 시안에는 있는데 구현이 안 된 분기 처리가 몇 개 있었다.

예를 들어 특정 코스 유형에서는 완료율 표시 방식이 다르다.

기간 설정과 안내 문구도 보완했다.

디자인과 구현이 일치하지 않으면 나중에 디자이너와 개발자 사이에 혼선이 생긴다.

미리 비교해서 차이를 잡는 게 중요하다.

## 빌드 인프라 개선

ESLint 빌드에서 경로 별칭 로드 실패 문제가 있었다.

`@/` 별칭을 인식하지 못해서 빌드가 실패했다.

ESLint는 TypeScript의 `paths` 설정을 기본적으로 읽지 않는다.

플러그인을 쓰면 되지만, 플러그인 버전에 따라 동작이 달라져서 불안정했다.

tsup 번들링을 도입해서 해결했다.

tsup은 경로 별칭을 번들링 단계에서 해석하기 때문에, ESLint 빌드와 충돌하지 않는다.

빌드 결과물 안에서 별칭이 실제 경로로 변환되니까 런타임에도 문제가 없다.

flat config 변환도 같이 진행해서 ESLint 설정을 단순화했다.

## 셸 스크립트 강화

서브에이전트용 셸 스크립트의 HTTP 에러 처리를 강화했다.

서브에이전트가 셸 스크립트를 실행할 때 네트워크 에러가 나면 적절히 처리되지 않았다.

에러 코드를 확인하고 재시도할지 에러를 반환할지 판단하는 로직을 추가했다.

파일 삭제 안전장치도 추가했다.

`rm -rf` 명령어가 위험한 경로에 대해 실행되지 않도록 가드를 넣었다.

실수로 중요한 파일이 삭제되는 것을 방지한다.

## 마무리

빌드 인프라는 눈에 안 보이지만 기능 개발의 기반이다.

기반이 흔들리면 기능 개발 속도도 떨어진다.

경로 별칭 문제 하나가 빌드를 전체 막고 있었으니까, 이걸 해결하니까 다른 작업도 진행할 수 있게 됐다.
