어제 설계한 대로 브라우저 실행 구조를 agent-browser 기반으로 전환했다.

마스터 에이전트만 브라우저를 준비할 수 있고, 실행 에이전트는 준비된 브라우저만 가져다 쓴다.

브라우저 소유권이 명확해지니까 세션 충돌이 깔끔하게 사라졌다.

## oh-my-opencode 의존성 제거

기존에는 oh-my-opencode라는 외부 의존성이 있었다.

이게 런타임에 에이전트를 로딩하고 관리하는 역할을 했는데, 우리가 제어할 수 없는 부분이 많았다.

버전이 바뀌면 동작이 달라지고 디버깅할 때 블랙박스라서 원인 추적이 어려웠다.

이 의존성을 제거하고 런타임 에이전트 카탈로그를 직접 구현했다.

외부 의존성 하나가 빠지니까 제어력이 확 올라갔다.

## 런타임 에이전트 카탈로그

에이전트 역할을 명시적으로 정의했다.

여섯 가지 역할로 나눴다.

마스터, 플래너, 실행자, 리포터, 체커, 탐색기.

각 역할마다 어떤 도구에 접근할 수 있고 어떤 권한을 가지는지 명확하게 정의했다.

마스터는 브라우저를 준비하고 전체 흐름을 조율한다.

플래너는 테스트케이스를 분석해서 실행 계획을 수립한다.

실행자는 계획을 받아서 실제 테스트를 수행한다.

리포터는 결과를 취합해서 Slack으로 보낸다.

체커는 실행 결과를 검증한다.

탐색기는 페이지 구조를 분석해서 셀렉터를 찾는다.

역할이 분리되니까 각 에이전트의 프롬프트를 독립적으로 최적화할 수 있었다.

이전에는 하나의 큰 프롬프트에서 모든 역할을 처리하려고 하니까 프롬프트가 길어지고 지시사항이 충돌했다.

이제는 각자 자기 역할에만 집중하는 짧은 프롬프트를 가진다.

## 지연 초기화

에이전트를 필요할 때만 초기화하도록 지연 초기화 패턴을 적용했다.

전체 에이전트를 한 번에 띄우니까 메모리를 너무 많이 먹었다.

탐색기는 플래너가 필요할 때만 호출되고, 체커는 실행자가 결과를 검증할 때만 호출된다.

평소에는 메모리에 올라가 있지 않다가, 호출되는 순간 초기화되어 실행된다.

메모리 사용량이 눈에 띄게 줄었다.

## macOS 키체인 팝업 완화

macOS에서 실행할 때 키체인 팝업이 계속 뜨는 문제를 완화했다.

키체인은 macOS의 비밀번호 관리 시스템인데, 인증 정보에 접근할 때마다 팝업이 뜤다.

팝업이 뜰 때마다 사용자가 수동으로 승인해야 해서 자동화가 끊긴다.

인증 정보를 미리 로드해서 팝업 빈도를 줄였다.

## 검증

타입체크, 테스트, 린트, 스모크 전부 통과했다.

## 마무리

의존성을 제거하고 직접 구현하니까 제어력이 확 올라갔다.

문제가 생기면 우리 코드 안에서 원인을 찾을 수 있으니까 디버깅이 훨씬 빨라졌다.
