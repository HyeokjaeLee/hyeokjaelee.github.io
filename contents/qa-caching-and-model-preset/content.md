어제 lane 동적 선택과 Slack 정리를 했으니, 오늘은 실행 비용을 줄이는 작업을 했다.

QA 에이전트는 실행할 때마다 LLM을 호출한다.

케이스가 30개면 planning, execution, inspection 단계에서 수십 번의 LLM 호출이 발생한다.

비용이 문제였다.

## Slack 출력 개선

먼저 Slack 결과 메시지를 더 읽기 쉽게 바꿨다.

어제 첨부 정책을 단순화했으니까 오늘은 내용 자체를 다듬었다.

케이스 결과를 간결하게 줄였다.

이전에는 통과한 케이스도 전체 실행 로그를 메시지에 담았다.

통과한 케이스는 "통과" 한 줄이면 충분하다. 실패한 케이스만 상세를 보여준다.

스크린샷에 페이지 URL을 포함시켰다.

실패한 케이스의 스크린샷만 봐서는 어느 페이지인지 알기 어려웠다.

URL이 있으면 바로 페이지로 이동해서 확인할 수 있다.

케이스 제목도 변경했다.

이전에는 케이스 번호가 제목이었다. "TC-005 통과" 이런 식.

이걸 검증 조건 우선으로 바꿨다. "로그인 실패 시 에러 메시지 표시 — 통과" 이런 식.

제목만 봐도 뭘 검증했는지 알 수 있다.

## 캐싱 정책

가장 큰 작업은 캐싱이었다.

같은 시트를 다시 실행할 때, 전체 planning을 처음부터 다시 하면 비용이 든다.

시트 단위 캐시를 만들었다.

한 번 planning한 결과를 캐시해둔다.

다음에 같은 시트를 실행하면 캐시된 planning 결과를 가져온다.

전체 planning을 생략하니까 실행 시작이 훨씬 빨라진다.

### 부분 재계획

캐시가 있다고 해서 무조건 캐시를 쓰면 안 된다.

시트가 변경되면 변경된 케이스만 다시 planning해야 한다.

전체 캐시를 버리지 않고, 변경된 케이스만 부분 재계획하도록 했다.

diff를 계산해서 변경된 부분만 새로 planning하고, 나머지는 캐시를 유지한다.

### 스킬 수명주기

성공한 케이스의 실행 지식을 스킬로 재사용하는 수명주기를 정립했다.

예를 들어 "로그인 페이지에서 아이디 입력 필드는 #username 셀렉터를 쓴다" 같은 지식이 실행 중에 발견되면, 이걸 스킬로 저장한다.

다음에 같은 페이지를 테스트할 때 이 스킬을 재사용한다.

매번 셀렉터를 새로 찾지 않아도 된다.

## preset 기능

런타임에 모델 설정을 인라인으로 관리하던 걸 provider별 preset 모듈로 분리했다.

이전에는 코드 안에 `model: "gpt-4"` 같은 설정이 직접 박혀 있었다.

모델을 바꾸려면 코드를 수정해야 했다.

provider별 preset 모듈을 만들었다.

Anthropic preset, OpenAI preset, ZAI preset 각각 모델 구성을 별도로 관리한다.

모델을 바꿀 때는 preset 파일만 수정하면 된다.

코드를 건드리지 않아도 모델 구성을 바꿀 수 있다.

> 설정은 코드와 분리하는 게 기본이다. 설정이 코드 안에 있으면 변경할 때마다 빌드를 다시 해야 한다.

## 마무리

캐싱으로 반복 실행 비용을 크게 줄였다.

같은 시트를 두 번째 실행할 때 planning 비용이 거의 0에 가깝다.

preset 분리로 모델 관리도 편해졌다.
