Alpha 환경에서 chromium 좀비 프로세스가 계속 쌓이는 문제를 근본적으로 해결한 날이었다.

## 좀비 프로세스 문제

QA 에이전트가 브라우저를 띄우고 테스트를 돌리다 보면 chromium 프로세스가 죽지 않고 좀비로 남는다.

좀비가 쌓이면 메모리를 잡아먹고 결국 서버가 뻗는다.

기존에는 SIGTERM을 보내서 종료를 시도했다.

문제는 SIGTERM이 좀비 프로세스에게 전달되지 않는다는 거다.

좀비는 이미 죽은 프로세스다.

부모 프로세스가 wait()를 호출하지 않아서 상태가 회수되지 않을 뿐이다.

## /proc/cmdline 직접 읽기

해결책은 `/proc` 파일 시스템을 직접 읽는 거였다.

`/proc/<pid>/cmdline`을 읽으면 프로세스의 시작 명령어를 알 수 있다.

이걸로 chromium 프로세스를 식별하고 부모-자식 관계를 추적해서 회수되지 않은 프로세스를 찾아낸다.

찾은 다음에는 부모 프로세스를 정리해서 자식 프로세스가 정상적으로 회수되도록 한다.

근본 원인을 해결하니까 좀비가 더 이상 쌓이지 않는다.

## 실행 큐 동시성 경합

실행 큐에서 동시성 경합 문제도 수정했다.

여러 lane이 동시에 큐에서 케이스를 꺼내려고 할 때 경합이 발생해서 같은 케이스가 중복 실행되는 경우가 있었다.

큐 접근에 락을 걸어서 한 번에 하나의 lane만 큐에서 꺼내도록 했다.

planning 캐시 갱신과 URL 변경 반영 이슈도 같이 잡았다.

## Langfuse 연동 설계

모든 LLM 호출을 추적하기 위해 Langfuse를 도입하기로 했다.

오늘은 설계만 잡았다.

provider별로 프록시를 분리해서 배포하는 구조다.

Anthropic, OpenAI, ZAI 세 provider 각각 별도 프록시 인스턴스를 둔다.

`x-session-id` 헤더로 세션을 추적해서 같은 실행에 속한 LLM 호출을 하나의 트레이스로 묶는다.

> Langfuse가 있으니까 나중에 "이 케이스에서 왜 3만 토큰을 썼지?" 같은 질문에 답할 수 있게 됐다.

## 마무리

좀비 프로세스 해결은 Alpha 환경 안정성에 직결되는 수정이었다.

Langfuse 트레이싱은 토큰 비용 분석의 기반이 된다.
