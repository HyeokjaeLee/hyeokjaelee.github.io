QA 에이전트를 Alpha 환경에 처음 배포한 날이었다.

ClawMux라는 사이드 프로젝트 플러그인도 같이 개발했다.

## ClawMux 플러그인

ClawMux는 Context-Gateway와 라우터를 통합한 플러그인이다.

LLM 기반 요청 분류기를 구현했다.

요청이 들어오면 LLM이 요청을 분석해서 적절한 provider로 라우팅한다.

Context-Gateway가 컨텍스트를 압축하고, 라우터가 적절한 모델로 보낸다.

이 두 가지를 하나의 플러그인으로 통합했다.

## QA 에이전트 Alpha 배포

DAG 기반 스케줄링을 구현했으니, 실제 Alpha 환경에 배포했다.

Graviton2 인스턴스로 마이그레이션하면서 큐 동시 실행 버그를 발견했다.

여러 lane이 동시에 큐에서 케이스를 꺼내려고 할 때 경합이 발생해서 같은 케이스가 중복 실행되는 버그였다.

큐 접근에 락을 걸어서 한 번에 하나의 lane만 큐에서 꺼내도록 수정했다.

## qa-sheet 모달 UX 개선

qa-sheet의 모달 UX를 개선했다.

이전에는 URL을 직접 입력해야 했다.

URL을 입력하는 건 사용자 친화적이지 않다.

모달 팝업으로 변경했다.

시트를 선택하면 모달이 뜨고, 거기서 설정을 입력하면 된다.

## 크래시 3중 방어

qa-sheet 첫 실행에서 EISDIR과 EEXIST 에러로 크래시가 났다.

디렉토리가 없을 때, 디렉토리 대신 파일이 있을 때, 권한이 없을 때 — 세 가지 케이스에서 크래시가 났다.

3중 방어 로직을 추가했다.

디렉토리가 없으면 생성하고, 파일이 있으면 디렉토리를 다른 경로에 생성하고, 권한이 없으면 에러 메시지를 반환한다.

## passed 비율 55%에서 76%

첫 실행 결과 passed 비율이 55%에서 76%로 올랐다.

DAG 기반 스케줄링의 효과였다.

의존성이 정확하게 처리되니까, 불필요한 blocked가 줄었다.

이전에는 그룹 단위로 blocked가 전파되서 통과할 수 있는 케이스도 blocked 되는 경우가 있었다.

DAG 기반에서는 정확한 의존성만 blocked를 유발한다.

> 통과율 21% 포인트 향상은 DAG 전환의 직접적인 효과다. 의존성 관리가 정확해지면 통과율은 자연스럽게 올라간다.

## 마무리

Alpha 배포가 성공적으로 끝났다.

통과율 76%는 의미 있는 숫자다.

여기서 더 올리려면 케이스 자체의 품질을 개선해야 한다.
