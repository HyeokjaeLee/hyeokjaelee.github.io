# AGENTS.md — 블로그 콘텐츠 관리 가이드

> 이 파일은 AI 에이전트가 블로그를 관리(포스트 작성·수정·구조 변경)할 때 참고하는 문서다.
> **블로그 포스트로 발행되지 않는다.** 콘텐츠 컬렉션 로더는 `**/content.md` 파일만 수집하므로
> `AGENTS.md` 라는 이름의 파일은 자동으로 제외된다.
>
> 이 파일 역시 `content.md` 로 이름을 바꾸거나 `<slug>/` 폴더 안에 넣으면 포스트로 인식되니 주의.

---

## 1. 디렉토리 구조

```
src/                       코드만 (이 디렉토리에 콘텐츠를 두지 않는다)
contents/                  모든 포스트 (루트, src 밖)
  <slug>/
    content.md             ← 포스트 본문 (반드시 이 파일명)
    assets/                ← 이미지 (Astro가 자동 최적화: WebP/srcset/LQIP/LCP)
public/
  <slug>/                  ← 동영상 (정적 서빙, 최적화 대상 아님)
```

- **이미지**는 `contents/<slug>/assets/` 에 두고 본문에서 상대경로 `assets/파일명` 으로 참조한다.
  → 빌드 시 자동으로 WebP 변환, srcset 생성, LQIP 블러 배경, 첫 이미지 LCP eager-loading 이 적용된다.
- **동영상**은 Astro가 최적화하지 않으므로 `public/<slug>/` 에 두고 절대경로 `/<slug>/파일명` 으로 참조한다.
- `<slug>` 가 곧 URL이 된다 (`/<slug>/`). 소문자, 하이픈 구분을 권장.

## 2. Frontmatter 스키마

모든 `content.md` 의 맨 위에 YAML 프론트매터가 필요하다. (`src/content/schema.ts` 가 검증)

```yaml
---
title: '포스트 제목'                      # 필수, 문자열
description: '포스트 요약 설명'           # 필수, 문자열 (목록 카드에 노출)
date: '2025-01-01'                        # 필수, YYYY-MM-DD (슬래그 정렬에 사용)
tags: [frontend, project]                 # 문자열 배열, 생략 시 []
titleImage: 'assets/cover.png'           # 선택, 상대경로 (제목 이미지). 없으면 생략
---
```

- `titleImage` 값은 `assets/파일명` (md 파일 기준 상대경로). `../images/...` 같은 옛 경로는 쓰지 않는다.
- 날짜는 반드시 `YYYY-MM-DD`. 잘못된 형식은 커밋 단계에서 차단된다.

## 3. 마크다운 → HTML 변환 규칙

### 3.1 변환 파이프라인

```
content.md
  │  remark 단계(md → mdast)
  ├─ remark-directive      :::directive 문법 파싱
  ├─ remark-image-optimize LQIP 블러 + 첫 이미지 LCP(eager) 주입
  ├─ remark-gallery         :::gallery → <figure class="gallery"> 메타데이터 보존
  │  mdast → hast(HTML AST)
  ├─ rehype-figure          이미지를 <figure>로 감싸고 alt 를 <figcaption> 으로 표시
  ├─ rehype-gallery         gallery figure 평탄화(이미지를 그리드 셀로) + 공유 캡션 보존
  ├─ rehype-slug            헤딩에 id 부여
  └─ rehype-autolink-headings 헤딩에 permalink 앵커(octicon) 삽입
  │
  ▼  prism 으로 코드 블록 하이라이트 + Astro 이미지 최적화 적용
HTML
```

> 순서가 중요하다. `rehype-figure` 가 `rehype-gallery` 보다 먼저 실행되어야 gallery 안 이미지도
> figure 로 감싸진 뒤 gallery 가 평탄화한다.

### 3.2 문법별 변환표

| 마크다운 | 렌더링 결과 | 비고 |
|---|---|---|
| `## 제목` ~ `######` | `<h2>`~`<h6>` + `id` + 앵커 | **본문은 `##` 부터.** `#`(h1)은 페이지 title 전용 |
| `**굵게**` | `<strong>` | 더 두껍게(font-black) |
| `*기울임*` | `<em>` | |
| `` `인라인코드` `` | `<code>` | 회색 배경 |
| ` ```lang ` 블록 | `<pre><code>` | prism 문법 강조, 어두운 배경 |
| `[텍스트](url)` | `<a>` | 파란색 + 호버 밑줄 |
| `- 항목` | `<ul>` | |
| `1. 항목` | `<ol>` | |
| `> 인용` | `<blockquote>` | 왼쪽 테두리 |
| `---` | `<hr>` | 구분선 |
| 표(`| a | b |`) | `<table>` | 넓으면 가로 스크롤 |
| `![캡션](assets/x.png)` | `<figure><img><figcaption>캡션</figcaption></figure>` | **alt 가 캡션으로 노출됨** |
| `![](assets/x.png)` | `<img>` | alt 없음 → 캡션 없음 |
| `:::gallery` (아래 참고) | `<figure class="gallery">` | 2-per-row 그리드 |

### 3.3 이미지 — alt 가 곧 캡션이다 (중요)

단독 이미지는 `rehype-figure` 에 의해 `<figure>` 로 감싸지며, **alt 텍스트가 `<figcaption>` 으로 화면에 노출**된다.

```md
<!-- 캡션 표시됨 -->
![로그인 화면 스크린샷](assets/login.png)
→ <figure><img ...><figcaption>로그인 화면 스크린샷</figcaption></figure>

<!-- 캡션 표시 안 됨 -->
![](assets/deco.png)
→ <img ...> (figure/figcaption 없음)
```

따라서:

- **alt 에 의미 있는 설명**을 쓴다 (화면에 보이므로 "image" 같은 무의미한 값은 피한다).
- 장식용이라 캡션이 싫으면 **alt 를 비운다** (`![](...)`) → 캡션 없이 이미지만 표시.
- 접근성(스크린리더)과 시각 캡션이 동일한 텍스트를 공유한다.

### 3.4 갤러리 — `:::gallery` (항상 한 행에 2개)

연속된 이미지를 2-per-row 그리드로 배치한다. (3/4열은 지원하지 않는다)

```md
:::gallery
![첫 번째 화면](assets/a.png)
![두 번째 화면](assets/b.png)
:::
```

→ `<figure class="gallery"><img><img></figure>` → CSS 가 2열 그리드로 렌더링.
이미지는 비율을 유지한 채 같은 행의 높이에 맞춰 정렬된다(`object-fit: contain`).

- **gallery 안 개별 이미지의 alt 는 캡션으로 표시되지 않는다.** (gallery 가 평탄화하므로)
- gallery 전체에 **공유 캡션**을 넣으려면 이미지 뒤에 한 줄 텍스트를 둔다:

```md
:::gallery
![a](assets/a.png)
![b](assets/b.png)

두 장 모두 같은 화면의 캡처다.
:::
```

→ `<figure class="gallery"><img><img><figcaption>두 장 모두 같은 화면의 캡처다.</figcaption></figure>`

### 3.5 동영상

동영상은 Astro가 변환하지 않으므로 raw HTML `<video>` 로 직접 작성하고, `public/<slug>/` 의 절대경로를 쓴다.

```md
<video autoplay muted loop playsinline preload="metadata" aria-label="데모 영상" width="600" height="400" style="aspect-ratio: 600 / 400;">
  <source src="/<slug>/demo.webm" type="video/webm" />
  <source src="/<slug>/demo.mp4" type="video/mp4" />
</video>
```

- webm + mp4 소스를 함께 제공(브라우저 호환).
- `aspect-ratio` 를 주면 로딩 중 레이아웃 시프트를 막는다.

## 4. 글쓰기 가이드라인 (말투 · 톤 · 구조)

기존 23개 포스트를 분석해 도출한 이 블로그 특유의 문체다. **이 톤을 유지해 글을 써야 한다.**

### 4.1 문체와 어조

- **준격식체, 선언형 종결.** `-다 / -했다 / -한다 / -같다 / -생각한다` 가 기본. `~요` 체는 사실상 쓰지 않는다.
- **1인칭 `나 / 내 / 나는 / 내가`.** `저/제가` 는 거의 안 쓴다.
- **경험 중심 서술.** 기술 글도 중립 문서가 아니라 "내가 뭘 선택/시도/싫어함/배웠다" 의 시점으로 쓴다.
- **독자 호칭은 절제.** "참고만 하고…", "~추천한다" 정도. 세일즈 톤 금지.
- **자신감 + 단서 균형.** 단정은 짓되 `개인적인 선호`, `~인 것 같다`, `~라고 생각한다` 로 여지를 둔다. 공식문서 링크로 보강.
- **유머는 드물게, 자조적으로.** 과하지 않게. `(?)` 같은 짧은 덧붙임, "짠내나는" 같은 자조 표현 OK. 빈번한 농담은 피한다.
- 개인 일화가 글의 중심(프로젝트 회고, 취업기, 여행글). 튜토리얼도 짧은 자전적 도입으로 시작.

### 4.2 문장 스타일

- **한 문장 = 한 문단** 이 자주다. 문단 사이 여백을 넉넉히.
- 연결어미(`-면서`, `-때문에`, `하지만`, `그런데`)로 길어지는 흐름형 문장. 다만 너무 길어지면 가독성 위해 끊는다.
- 의문문·감탄문은 거의 안 쓴다(전체 코퍼스에서 의문 6회, 감탄 1회).
- 개념 설명 순서: ① 정의/맥락 → ② 왜 다뤘는지 → ③ 구현/사용 → ④ 트레이드오프·실패·개인 판단.
- 비유/한 줄 요약으로 단순화(예: 디자인 패턴 = "선배 개발자들의 족보").

### 4.3 상투적 표현 (이 블로그 특유)

- 전환: `우선`, `그리고`, `결국`, `추가적으로`, `그 과정에서`, `하지만`, `다음과 같다`, `한마디로 요약하자면`
- 글 목적 선언: `~공유해보려 한다`, `~정리해봤다`, `~남겨보려 한다`
- 사고 표현: `~느꼈다`, `~생각했다`, `~생각한다`, `~인 것 같다`
- 마무리: `참고 자료` 섹션, 단서, 다음 생각

**영어 기술 용어는 원문 그대로** 쓰고 한국어 조사를 붙인다.
`Next.js`, `Gatsby`, `TypeScript`, `SSR`, `SSG`, `Tailwind`, `NestJS`, `Atomic Design Pattern`.
한국어 혼용(리액트, 자바스크립트, 컴포넌트, 배포, 토이 프로젝트)도 자연스럽게 섞는다.
추상적 동기부여 언어보다 구체적 엔지니어링 명사·결정 동사를 선호한다.

### 4.4 포스트 구조

- **도입:** 즉각적인 개인 맥락이나 문제 상황 → 왜 이 글을 쓰는지. (튜토리얼은 정의로 시작하기도)
- **헤딩:** `##` 메인 → `###` 서브 → 필요시 `####` 디테일. 보통 2~3 단계. (본문에 `#` h1 은 쓰지 않는다)
- **단계 번호(1. 2. 3.) 구조는 드뭄.** 비교/기준/요약에만 글머리 기호.
- **TL;DR / 결론 섹션은 없음.**
- **마무리 유형:** 참고 자료 추천 / 단서 / 개인적 다음 생각 / 짧은 회고. 동기부여형 범용 결론은 피한다.
- **길이:** 본문 약 84~1400 토큰, 중앙값 약 486. 튜토리얼은 짧게, 회고는 길게.

### 4.5 콘텐츠 관례

- **이미지:** 튜토리얼은 드물게, 프로젝트/여행 회고는 많이(10~15장). 연속 이미지는 `:::gallery` 로.
- **코드:** ` ```ts `, ` ```tsx `, ` ```javascript `, ` ```json ` 등 언어 명시.
- **표:** 비교/기준에만. (`good-commit-message` 참고)
- **인용구(`>`):** 덧붙임, 단서, 유머, 참고 자료 목록용. 정식 인용 아님.
- **링크:** 기술 글은 공식문서·GitHub·관련 글. 회고/여행 글은 이미지 위주.
- **트레이드오프 명시:** "A 대신 B를 선택한 이유", 제약(무료 호스팅), 마이그레이션 실패, 유지비 등 선택의 맥락을 서술.

### 4.6 글쓰기 체크리스트

1. `나는/내가` + 구체적 상황/불편/프로젝트 맥락으로 시작.
2. 글 목적을 `~공유해보려 한다` / `~정리해보려 한다` 로 선언.
3. `##` 섹션 + `###` 서브구조. 본문에 `#` 금지.
4. 영어 라이브러리/도구명은 원문 그대로 + 한국어 조사.
5. 각 선택을 제약·대안·결과로 설명.
6. `-다/-했다/-한다` 종결, 한 문장 한 문단.
7. 가끔 `(?)`, 인용구 덧붙임, 자조적 한마디. 잦은 농담 금지.
8. 마무리는 단서 / 추천 / 참고 자료 / 다음 생각. 범용 동기부여 결론 금지.
9. 회고적 불확실함(`~같다`, `~생각한다`)을 유지하되 구체적 권고는 한다.
10. 오탈자/띄어쓰기 오류는 의도치 않게 재현하지 않는다.

## 5. 커밋 전 검증 (Husky pre-commit)

`contents/**/content.md` 를 커밋하면 자동으로 검증된다. 실패 시 커밋 차단.

1. **Frontmatter 스키마 검증** — `scripts/validate-post.ts` 가 zod 스키마로 필수 필드/날짜 형식/태그 배열 점검. 필드별 에러 출력.
2. **중국어(한자) 감지 금지** — CJK 표의문자가 감지되면 차단. 한국어 Hangul 은 허용. (어느 줄인지 라인 번호로 알려줌)
3. **Astro 풀 빌드** — md 변경 시 `astro build` 가 전체 실행되어 렌더링 에러까지 잡는다.

> `AGENTS.md` 는 `content.md` 가 아니므로 이 검증 대상이 아니다.

## 6. 요약 — 새 포스트 만들기

```
contents/my-new-post/
  content.md       ← 프론트매터 + 본문
  assets/          ← 이미지들
```
- 동영상이 있으면 `public/my-new-post/` 에 파일 두고 `/<slug>/파일명` 참조.

1. 프론트매터(title/description/date/tags, 필요시 titleImage) 작성.
2. 본문은 `##` 부터 시작, 이 가이드의 문체·구조 준수.
3. 단독 이미지는 의미 있는 alt(캡션으로 보임), 연속 이미지는 `:::gallery`.
4. 커밋하면 pre-commit 이 스키마·중국어·빌드를 자동 검증.
