사이드 프로젝트인 OpenCode auto-fallback 플러그인을 하루 종일 개선한 날이었다.

## auto-fallback이란

LLM 호출 시 에러가 발생하면 자동으로 다른 모델로 전환하는 플러그인이다.

한 모델이 응답하지 않으면 fallback 모델로 요청을 다시 보낸다.

서비스 중단 없이 LLM 장애에 대응할 수 있다.

## 에러 분류 고도화

에러를 두 가지로 분류했다.

즉시 전환해야 하는 에러와 재시도 후 전환해야 하는 에러.

네트워크 타임아웃은 재시도해볼 만하다.

하지만 모델이 지원하지 않는 기능 에러는 재시도해도 같은 결과다.

에러 유형에 따라 즉시 전환할지 재시도할지 판단한다.

### 모델 단위 장애 추적

모델별로 장애 이력을 추적한다.

특정 모델이 연속으로 에러를 내면, 잠시 그 모델을 우회하는 식이다.

장애 빈도와 패턴을 분석해서 fallback 우선순위를 동적으로 조정한다.

## 설정 구조 단순화

기존 설정 파일이 복잡했다.

첫 실행 시 설정 파일을 자동으로 생성하도록 바꿨다.

사용자가 설정을 처음부터 작성할 필요 없이, 기본값으로 시작해서 필요한 부분만 수정하면 된다.

## npm 자동 업데이트

npm 레지스트리에서 새 버전이 나오면 자동으로 업데이트하는 기능을 추가했다.

사용자가 수동으로 업데이트하지 않아도 항상 최신 버전을 쓸 수 있다.

## 테스트 확장

테스트를 23개에서 65개로 확장했다.

에러 분류, fallback 우선순위, 자동 업데이트 각각에 대한 테스트를 추가했다.

테스트가 많아지니까 수정했을 때 회귀 버그를 빠르게 잡을 수 있다.

영문 README와 프로젝트 구조 문서도 작성했다.

## 연속 배포

v0.0.5에서 v0.0.11까지 하루에 7버전을 배포했다.

작은 단위로 자주 배포하니까 피드백 루프가 빠르다.

## 마무리

하루 집중해서 플러그인을 크게 개선했다.

에러 분류와 모델 단위 추적이 들어가니까 fallback이 훨씬 똑똑해졌다.
