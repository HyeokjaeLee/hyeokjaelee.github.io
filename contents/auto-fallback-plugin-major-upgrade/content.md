사이드 프로젝트인 auto-fallback 플러그인을 하루 종일 개선한 날이었다.

이 플러그인은 LLM 호출 시 에러가 발생하면 자동으로 다른 모델로 전환하는 도구다.

하루 종일 이것만 했더니 v0.0.5에서 v0.0.11까지 7버전을 배포했다.

## 에러 분류 고도화

기존에는 에러가 나면 무조건 다른 모델로 전환했다.

하지만 모든 에러가 전환을 필요로 하는 건 아니다.

에러를 두 가지로 분류했다.

즉시 전환해야 하는 에러와 재시도 후 전환해야 하는 에러.

네트워크 타임아웃은 일시적일 수 있으니까 재시도해볼 만하다.

하지만 모델이 지원하지 않는 기능 에러는 재시도해도 같은 결과다.

이런 건 즉시 전환하는 게 맞다.

에러 유형에 따라 전환 전략을 다르게 적용했다.

### 모델 단위 장애 추적

모델별로 장애 이력을 추적하는 기능을 추가했다.

특정 모델이 연속으로 에러를 내면 장애 빈도와 패턴을 기록한다.

패턴을 분석해서 fallback 우선순위를 동적으로 조정한다.

특정 모델이 자주 장애를 일으키면 fallback 순위를 낮춘다.

## 설정 구조 단순화

기존 설정 파일이 복잡했다.

사용자가 처음 쓸 때 뭘 설정해야 할지 모를 정도였다.

첫 실행 시 설정 파일을 자동으로 생성하도록 바꿨다.

기본값으로 설정 파일을 만들어주고, 사용자는 필요한 부분만 수정하면 된다.

설정이 없으면 동작하지 않던 이전 방식에서, 설치하면 바로 동작하는 방식으로 바뀌었다.

## npm 자동 업데이트

npm 레지스트리에서 새 버전이 나오면 자동으로 업데이트하는 기능을 추가했다.

사용자가 수동으로 `npm update`를 치지 않아도 항상 최신 버전을 쓸 수 있다.

자동 업데이트 후 재시작이 필요하다는 안내도 함께 보여준다.

## 테스트 확장

테스트를 23개에서 65개로 확장했다.

에러 분류, fallback 우선순위, 자동 업데이트, 설정 자동 생성 각각에 대한 테스트를 추가했다.

테스트가 많아지니까 수정했을 때 회귀 버그를 빠르게 잡을 수 있다.

특히 에러 분류 로직은 분기가 많아서 테스트가 없으면 디버깅이 어렵다.

영문 README와 프로젝트 구조 문서도 작성했다.

## 연속 배포

v0.0.5에서 v0.0.11까지 하루에 7버전을 배포했다.

작은 단위로 자주 배포하니까 피드백 루프가 빠르다.

버그를 발견하면 바로 수정하고 다음 버전을 배포한다.

큰 단위로 모아서 배포하는 것보다 이 방식이 개발 속도가 빠르다.

## 마무리

하루 집중해서 플러그인을 크게 개선했다.

에러 분류와 모델 단위 추적이 들어가니까 fallback이 훨씬 똑똑해졌다.

설정 자동 생성으로 진입 장벽도 크게 낮아졌다.
