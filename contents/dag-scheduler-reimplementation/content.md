실행 모델을 그룹 기반에서 DAG 기반으로 전면 재구현한 날이었다.

지금까지는 케이스를 그룹으로 묶어서 실행했다.

그룹 단위로 실행하고, 그룹 단위로 재시도하고, 그룹 단위로 blocked 처리했다.

그런데 그룹보다 더 정교한 의존성 관리가 필요했다.

## 그룹 기반의 한계

그룹 기반에서는 케이스 A가 케이스 B에 의존하면 같은 그룹에 넣었다.

같은 그룹은 순차 실행된다.

하지만 케이스 C가 A에만 의존하고 B에는 의존하지 않아도, 같은 그룹이면 B가 끝날 때까지 기다려야 했다.

불필요한 대기 시간이 발생한다.

A가 끝나면 C는 바로 실행할 수 있는데도, B가 끝날 때까지 기다리는 거다.

그룹 단위 실행은 간단하지만 병렬성을 제한한다.

## DAG 기반 스케줄링

의존성을 그래프로 표현했다.

각 케이스는 노드이고, 의존성은 간선이다.

케이스 A → 케이스 B 간선이 있으면, B는 A가 끝나야 실행할 수 있다.

위상 정렬로 실행 순서를 결정한다.

위상 정렬은 의존성을 위반하지 않으면서 실행 가능한 순서를 찾는 알고리즘이다.

위상 정렬 결과에 따라 의존성이 없는 케이스들을 병렬로 실행한다.

A와 B에 모두 의존하지 않는 C는 A, B와 동시에 실행할 수 있다.

A에만 의존하는 D는 A가 끝나면 바로 실행된다.

B를 기다릴 필요가 없다.

### 병렬 실행 스케줄러

위상 정렬 결과를 기반으로 병렬 실행 스케줄러를 구현했다.

실행 가능한 케이스들을 큐에 넣고, 가용한 lane 수만큼 병렬로 실행한다.

하나가 끝나면 의존성을 확인해서 새로 실행 가능해진 케이스를 큐에 추가한다.

이 과정이 모든 케이스가 끝날 때까지 반복된다.

## 17개 파일 수정

전면 재구현이라서 파일 17개를 수정했다.

기존 그룹 기반 실행 코드를 전부 걷어내고, DAG 기반 코드로 교체했다.

코드 양은 비슷했지만 구조가 완전히 달라졌다.

## 중요 버그 4개 수정

재구현 과정에서 버그 4개를 발견해서 수정했다.

순환 의존성 감지, 부분 실패 시 롤백, lane 할당 경쟁 조건, 캐시 무효화 누락.

순환 의존성은 A가 B에 의존하고 B가 A에 의존하는 상황이다.

순환이 있으면 위상 정렬이 불가능하다.

순환 감지 로직을 추가해서, 순환이 발생하면 에러를 반환하도록 했다.

> DAG에서 순환은 치명적이다. 순환이 있으면 영원히 실행이 멈추지 않는다. 위상 정렬 전에 반드시 순환을 감지해야 한다.

## 실제 QA 시트 검증

실제 QA 시트로 테스트했다.

위키 문서에 적힌 테스트 케이스를 그대로 실행해서, DAG 스케줄링이 올바르게 동작하는지 확인했다.

의존성이 올바르게 처리되고, 병렬 실행이 의도대로 동작하는 것을 확인했다.

## 마무리

그룹 기반에서 DAG 기반으로 바꾸니까 실행 시간이 줄었다.

불필요한 대기가 사라졌기 때문이다.

DAG는 복잡해 보이지만, 한 번 구현해두면 의존성 관리가 자동으로 처리된다.
