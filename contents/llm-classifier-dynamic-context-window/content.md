ClawMux의 요청 분류기를 키워드 기반에서 LLM 기반으로 전환한 날이었다.

## 키워드 분류기의 한계

기존에는 요청에 포함된 키워드를 점수화해서 복잡도를 판단했다.

"코드 분석", "리팩토링" 같은 키워드가 있으면 무거운 요청으로 분류하는 식이다.

이 방식의 한계는 맥락을 이해하지 못한다는 거다.

"코드 분석 결과를 한 줄로 요약해"는 가벼운 요청인데, "코드 분석" 키워드 때문에 무거운 요청으로 잘못 분류된다.

반대로 "이 버그 원인이 뭘까"는 복잡한 추론이 필요한데, 키워드만 보면 가벼운 요청으로 보인다.

## LLM 분류기

LLM이 요청을 읽고 복잡도를 직접 판단하도록 했다.

요청을 받으면 분류 전용 LLM이 한 번 읽고, LIGHT/MEDIUM/HEAVY 세 단계로 분류한다.

분류 결과에 따라 적절한 provider와 모델로 라우팅한다.

비용이 드는 것 같지만, 분류용 LLM은 가장 저렴한 모델을 쓰고 응답을 한 글자로 강제하니까 토큰 사용량이 극히 적다.

> reasoning을 비활성화하고 `max_tokens=1`로 설정하면 분류 비용이 사실상 무료에 가깝다.

## 동적 컨텍스트 창 해석

모델마다 컨텍스트 윈도우 크기가 다르다.

GPT-4o는 128K, Claude는 200K, 가벼운 모델은 8K.

Context-Gateway가 컨텍스트를 압축할 때, 각 모델의 컨텍스트 윈도우 크기를 모르면 최적의 압축 임계값을 정할 수 없다.

SDK를 통해 모델 메타데이터를 조회해서 컨텍스트 윈도우 크기를 가져온다.

그리고 모델별로 최적의 압축 임계값을 동적으로 계산한다.

128K 모델에게는 압축을 덜 하고 원본에 가깝게 전달하고, 8K 모델에게는 더 공격적으로 압축한다.

## qa-sheet-writer 프롬프트 개선

QA 에이전트의 sheet-writer 프롬프트를 개선했다.

`skipAgentTest` 판단 기준을 명확히 했다.

어떤 케이스는 에이전트가 자동화할 필요가 없다.

예를 들어 단순 페이지 이동 검증은 에이전트 없이도 확인할 수 있다.

이런 케이스를 에이전트가 알아서 판단해서 건너뛰도록 기준을 정리했다.

메모 작성 지침도 개선했다.

각 케이스에 어떤 메모를 남길지 가이드라인을 잡았다.

## 마무리

LLM 분류기 전환 후 라우팅 정확도가 눈에 띄게 올랐다.

동적 컨텍스트 창 해석으로 각 모델의 성능을 최대한 끌어쓸 수 있게 됐다.
