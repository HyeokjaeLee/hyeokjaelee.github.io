ClawMux 플러그인의 핵심 기능을 구현한 날이었다.

요청 분류기와 동적 컨텍스트 창 해석, 두 가지를 만들었다.

## LLM 기반 요청 분류기

ClawMux에 요청이 들어오면 LLM이 요청을 분석해서 분류한다.

이전에는 키워드 매칭으로 분류했다.

요청에 "코드"라는 단어가 있으면 코드 관련 요청으로 분류하는 식이다.

키워드 매칭은 빠르지만 정확하지 않다.

"코드를 실행해줘"와 "코드 리뷰해줘"는 둘 다 "코드"를 포함하지만 필요한 모델이 다르다.

LLM이 요청의 의도를 파악해서 분류하니까 정확도가 올라갔다.

### reasoning 비활성화

LLM이 분류할 때 reasoning을 비활성화했다.

reasoning을 켜면 LLM이 생각 과정을 출력하는데, 분류에는 필요 없다.

결과만 빨리 반환하는 게 중요하다.

`max_tokens=1`로 설정해서 LLM이 분류 라벨 한 글자만 반환하도록 했다.

한 글자만 반환하니까 토큰 사용량이 극단적으로 적다.

비용이 거의 들지 않는다.

## 동적 컨텍스트 창 해석

모델마다 컨텍스트 윈도우 크기가 다르다.

128K를 지원하는 모델도 있고, 8K만 지원하는 모델도 있다.

요청의 컨텍스트가 50K인 경우, 128K 모델에게는 그대로 보내도 되지만 8K 모델에게는 압축이 필요하다.

동적 컨텍스트 창 해석은 요청 컨텍스트 크기를 측정하고, 대상 모델의 컨텍스트 윈도우에 맞춰서 압축 여부를 결정한다.

128K 모델에게는 덜 압축하고 8K 모델에게는 더 공격적으로 압축한다.

이전에는 고정된 압축 비율을 써서 작은 모델에게는 부족하고 큰 모델에게는 과도했다.

동적 해석으로 각 모델에 최적화된 압축을 적용한다.

> 컨텍스트 압축은 비용과 품질의 트레이드오프다. 너무 압축하면 정보가 손실되고, 너무 덜 압축하면 비용이 든다. 모델별 컨텍스트 윈도우에 맞춰서 최적점을 찾는 게 핵심이다.

## qa-sheet-writer 프롬프트 개선

qa-sheet-writer의 `skipAgentTest` 판단 기준을 정리했다.

에이전트가 자동화할 필요가 없는 케이스를 명확히 구분한다.

예를 들어 "페이지가 열리는지 확인" 같은 단순 검증은 에이전트 없이도 할 수 있다.

이런 케이스를 에이전트가 판단해서 건너뛰도록 기준을 정의했다.

메모 작성 지침도 개선했다.

PM이 결과를 읽을 때 어떤 정보가 필요한지 기준을 잡았다.

실패한 케이스에 "왜 실패했는지", "재현 방법", "예상 동작" 세 가지가 들어가도록 지침을 정했다.

## 마무리

LLM 분류기로 라우팅 정확도가 올라갔다.

동적 컨텍스트 창 해석으로 불필요한 압축을 줄였다.
