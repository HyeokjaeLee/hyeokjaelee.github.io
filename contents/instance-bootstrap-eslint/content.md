회귀 버그를 추적하고 ESLint 설정을 대폭 강화한 날이었다.

## InstanceBootstrap 회귀 버그

InstanceBootstrap이 정상적으로 초기화되지 않는 회귀 버그가 보고됐다.

인스턴스가 생성되지 않으니까 서비스가 아예 동작하지 않는 치명적인 버그였다.

원인을 추적해보니 리팩토링 과정에서 `init` 파라미터가 제거된 게 문제였다.

리팩토링으로 함수 시그니처를 단순화하면서 `init` 파라미터를 없앴다.

함수가 더 깔끔해졌고 테스트도 통과했다.

그런데 레거시 라우트가 이 파라미터에 의존하고 있었다.

새로 작성한 테스트는 새 시그니처를 기준으로 통과했지만, 레거시 코드는 이전 시그니처를 호출하고 있었다.

파라미터가 사라지니까 레거시 라우트 초기화가 안 됐고, 결과적으로 인스턴스가 정상적으로 생성되지 않았다.

### 왜 테스트가 이걸 잡지 못했나

레거시 라우트에 대한 테스트가 없었다.

새 코드는 테스트가 있었지만, 레거시 코드는 테스트 커버리지 밖이었다.

리팩토링할 때 레거시 경로까지 테스트했다면 잡을 수 있었다.

PR 설명을 작성하고 dev 브랜치에 반영했다.

> 리팩토링은 기능을 변경하지 않아야 한다. 하지만 숨어있는 의존성이 있으면 의도치 않게 기능이 깨진다.

## ESLint v9 flat config

auto-fallback 플러그인에 ESLint v9 flat config를 적용했다.

ESLint v9는 기존 `.eslintrc` 방식을 버리고 flat config라는 새로운 설정 방식을 도입했다.

설정 파일이 하나로 평면화되니까 관리가 편해진다.

80개 이상의 엄격한 TypeScript 규칙을 적용했다.

### 경로 별칭 의무화

상대 경로 import를 금지하고 `@/` 별칭을 의무화했다.

`../../../utils/helper` 같은 상대 경로는 파일 위치가 바뀌면 경로도 바꿔야 한다.

`@/utils/helper`처럼 별칭을 쓰면 파일 위치와 무관하게 동일한 경로를 쓸 수 있다.

정렬 규칙도 추가해서 import 순서를 일관되게 만들었다.

import 순서가 제각각이면 코드 리뷰 때 불필요한 변경사항이 많이 생긴다.

Prettier 설정도 함께 적용해서 포맷팅을 통일했다.

엄격한 규칙을 적용하니까 코드 품질이 올라가지만, 동시에 기존 코드를 전부 수정해야 해서 시간이 많이 걸렸다.

## 마무리

회귀 버그는 리팩토링의 함정이다.

보이지 않는 의존성을 제거할 때는 전수 조사가 필요하다.

테스트가 없는 코드 경로는 리팩토링하면 안 된다.
