QA Sheet가 두 번째 실행에서 멈추는 문제를 해결하고, 권한을 정리한 날이었다.

## QA Sheet 두 번째 실행 멈춤

같은 시트로 QA를 두 번째 실행하면 멈춰버리는 문제가 있었다.

첫 번째 실행은 잘 되는데, 두 번째는 응답이 안 온다.

원인을 추적하는 데 시간이 길렸다.

에이전트 코드 문제인 줄 알고 한참을 디버깅했다.

결국 원인은 LLM 제공 측의 장애였다.

첫 번째 실행에서 컨텍스트가 크게 쌓인다.

케이스가 20~30개면 실행하면서 브라우저 스냅샷, 스크린샷, 추론 과정이 전부 컨텍스트에 누적된다.

두 번째 실행에서 이 컨텍스트를 다시 보내니까 LLM이 처리를 못 하는 거였다.

컨텍스트가 너무 크면 LLM이 응답을 포기한다.

### 실행 시간 축소

해결책은 컨텍스트가 덜 쌍이도록 실행 시간을 줄이는 거였다.

전체 실행 시간을 1시간에서 20분으로 축소했다.

실행이 빨리 끝나면 컨텍스트가 덜 쌍인다.

불필요한 대기 시간을 제거하고, 케이스 간 전환을 빠르게 만들었다.

20분으로 줄이니까 두 번째 실행도 멈추지 않고 정상 동작했다.

## 노션 API 호출 제거

QA Sheet가 노션 페이지 제목을 가져오기 위해 API를 호출하고 있었다.

이 호출이 실행 흐름에 병목이었다.

노션 API 응답이 느리면 QA 시작 자체가 지연된다.

모달에서 입력받은 값을 시트 제목으로 직접 사용하도록 변경했다.

API 호출이 빠지니까 실행 시작이 훨씬 빨라졌다.

사용자가 시트 이름을 입력하면 바로 실행이 시작된다.

## 강사 접근 권한 분리

업무 프로젝트에서 강사 역할의 접근 권한을 정리했다.

강사가 접근할 필요가 없는 페이지의 접근을 제외했다.

특정 전용 문구를 삭제하고, 진단 태그 설정 링크를 조건부로 숨겼다.

강사 역할로 로그인했을 때 보이는 메뉴가 달라진다.

불필요한 메뉴가 보이면 사용자가 혼란스럽다.

Alpha 배포를 완료했다.

## 마무리

QA Sheet 타임아웃은 LLM 제공측 장애가 원인이었지만, 실행 시간 단축으로 우회할 수 있었다.

근본 원인을 고칠 수 없으면 우회라도 해야 한다.

API 호출 제거도 작지만 효과적인 최적화였다.
